  - **MySQL root 空口令**，读取 7 个数据库
- **产出**：8 页渗透测试报告，含信息收集、漏洞详情、未验证风险点、P0/P1/P2 分级修复建议

### 2. DVWA Web 漏洞实战

手工复现四类 OWASP Top 10 漏洞，每类都追到源码层面确认成因。

| 漏洞 | 做到什么程度 |
|---|---|
| **SQL 注入** | `order by` 判断列数 → `union select` 定位回显位 → 取出库名与数据库用户；理解预编译（参数化查询）为根本防御 |
| **XSS** | 反射 / 存储 / DOM 三型全部复现；DOM 型中 payload 落在 `<select>` 容器内不执行，通过闭合容器跳出后才触发；利用存储型构造请求窃取会话 Cookie |
| **文件上传** | Low 难度上传 PHP 脚本实现命令执行；Medium 难度下用 Burp 将 `Content-Type` 由 `application/x-php` 改为 `image/jpeg` 绕过校验 |
| **CSRF** | 三档难度全通关；Medium 发现 `stripos` 子串判断可被子域名 `192.168.59.128.evil.com` 绕过；High 验证 Token 一次性，重放返回 302 + `CSRF token is incorrect` |

另外完成**水平 / 垂直越权**与**敏感信息泄露**（`.git`、`.env`、备份文件）的探测练习。

## 我认为值得记录的技术细节

**1. 判断列数不是靠猜**
`order by` 从 1 开始递增，直到报错，报错前一个数字就是列数。`order by 2` 正常、`order by 3` 报错 → 2 列。

**2. 端口开放 ≠ 端口暴露**
`ss -tlnp` 里 `LISTEN 127.0.0.1:3306` 和 `LISTEN *:80` 的风险完全不同。前者只有本机能连，后者整个网段都能访问。判断依据是**监听地址**。

**3. XSS 要先判断注入上下文**
`<script>alert(1)</script>` 落在 `<div>` 里会执行，落在 `<option>` 或属性值里不会。DOM 型里 payload 被困在 `<select>` 内时，需要 `</option></select>` 先跳出容器。

**4. 只校验客户端字段等于没校验**
文件上传 Medium 只检查 `Content-Type`，而这是客户端可控的字段。用 Burp 改成 `image/jpeg` 就能绕过。

**5. 报告里没验证的事不下结论**
写「待确认」比写一个错结论强。这是我做资产梳理时体会最深的一条：扫描器说开放，不等于真的可利用。

**6. 「包含」不等于「等于」**
DVWA CSRF 的 Medium 用 `stripos($referer, $server_name)` 判断来源。只要 Referer 里任意位置出现服务器名就放行，于是 `192.168.59.128.evil.com`（攻击者自己的子域名）也能通过。
字符串匹配的安全判断，永远要问一句：**能不能构造出「包含但不等于」的输入**？
