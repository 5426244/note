# 资产梳理报告 · 本地实验网段

## 概述

对本地 VMware NAT 网段做资产梳理：主机发现 → 全端口扫描 → 服务识别 → 风险分析。

- **测试范围**：192.168.59.0/24、127.0.0.1（仅本地实验环境）
- **工具**：Nmap 7.94
- **报告**：[资产梳理报告_本地网段.docx](./资产梳理报告_本地网段.docx)

## 做了什么

1. **主机发现**：`nmap -sn 192.168.59.0/24`，扫 256 个地址，发现 4 台存活主机
2. **端口与服务**：`sudo nmap -sV -p- 127.0.0.1`，65532 个端口关闭，3 个开放
3. **二次验证**：对每个开放端口用 `ss -tlnp` 确认监听地址
4. **报告**：P0/P1/P2 分级整改建议 + 后续验证计划

## 核心发现

| 端口 | 服务 | 监听地址 | 风险 |
|---|---|---|---|
| 22 | OpenSSH 9.3p2 | `*:22` | 低（版本新，主要风险弱口令） |
| 80 | Apache 2.4.57 | `*:80` | **高：对外监听且承载 DVWA / Pikachu 靶场** |
| 3306 | MariaDB 10.11.4 | `127.0.0.1` | 低（仅本机监听） |

## 最大的收获

**"端口开放"和"端口暴露"是两回事。**

一开始扫描发现 3306 开放，看上去像风险点。但用 `ss -tlnp` 一查：

```
LISTEN 0  80  127.0.0.1:3306  0.0.0.0:*  users:(("mariadbd",pid=966,...))
```

绑定在回环地址，**只有本机能连，风险低**。而 80 端口是：

```
LISTEN 0  511  *:80  *:*  users:(("apache2",pid=3128,...))
```

`*` 表示所有网卡，**整个网段都能访问**，而上面跑的是漏洞靶场——这才是真正该修的。

> 扫描告诉你在哪里，验证告诉你是否成立。**判断依据是监听地址，不是端口是否开放。**

## 写报告的原则

**没验证的事不下结论，标"待确认"。**

把猜测写成事实，是新手报告最常见的扣分点。
